# Building the reconstruction

Run `make check` from the repository root. This compiles the reconstructed
modules into `.build/libmaven-reconstruction.a`, links the investigation
Word List probe, and runs the focused host tests. Generated files are ignored.
`CC`, `AR`, `PYTHON`, `CFLAGS`, and `BUILD_DIR` can be overridden. Header
dependencies are generated by the compiler.

The historical `toolchain_probe.c` is deliberately separate: it is the input
used in the recovered THINK compiler experiments and has a classic-Mac entry
point and type assumptions. It is not part of the semantic library.

The first combined build compiled 21 reconstructed C modules with C99,
optimization, and warnings treated as errors. All 28 focused tests passed.
The linked probe reproduced all 149 original ordered emissions in the four
saved Word List captures. Linking every object into a macOS dynamic library
also succeeded, checking for unresolved internal symbols across the complete
set, including modules the probe does not reference.

For a hash-checked data-file invocation, use `scripts/run_word_enumerator.py`.
The raw `.build/word-enumerator` is an investigation executable and expects
the already verified Maven data fork; it does not identify arbitrary inputs.

This is a host semantic build, not a complete Maven application, a 68k ABI
replacement, or proof of byte-identical output from the original compiler.
Toolbox adapters, application entry/event loop, game/search reconstruction,
and full-game original-runtime validation remain incomplete. Per-module
evidence and limits are recorded in `analysis/toolchain/`.
